# Trusted bounded command hooks

Ticket T-0118, story S-025. Initial immutable boundary is T117 final proof `d4a4baa1be4e304e40c1001dc1e231e555292d98`. This contract requires independent approval before Rust implementation. Later stack integration retains only this ticket's own changes and repeats focused integration verification.

## Public sources and existing boundaries

Read 2026-10-11:

- [Rust catch_unwind](https://doc.rust-lang.org/std/panic/fn.catch_unwind.html): catches unwinding panics; ordinary failures use Result. Process abort and nontermination remain outside this mechanism. Dropping an unknown panic payload can itself panic.
- [Rust Mutex](https://doc.rust-lang.org/std/sync/struct.Mutex.html): a held guard excludes other lock users; poisoning is advisory. Explicit callback admission and rollback are required rather than relying on poisoning.
- [KiCad 9 design rule checking](https://docs.kicad.org/9.0/en/pcbnew/pcbnew.html#design-rule-checking): motivates a useful design validator. Viamind's existing scoped checker and coverage determine the supported checks; no imported implementation or complete manufacturing claim.

`Engine::transaction` applies original command deltas, rolls them back on Result failure, coalesces, allocates TxId, clears redo, emits and records history. Typed, dynamic, batch and prepared PCB branch commits enter this boundary. Undo and redo have separate original paths. `EngineHandle::mutate` invalidates AutoDRC once per successful design change and runs repaint callbacks after releasing its engine mutex. Native save/replacement takes a separate file mutex before the engine mutex. These ordering and ownership boundaries remain authoritative.

## Trusted registration and transient state

Supply Rust APIs for trusted in-process pre validators and post callbacks on Engine and EngineHandle. They accept Send + Sync closures, never scripts, shell commands, executable paths, MCP function bodies or remotely supplied callback code. IDs are unique across both kinds, trimmed ASCII identifiers of 1..64 bytes. Registration order is deterministic; duplicate/invalid IDs and capacity refuse without changing configuration. There are at most sixteen pre slots including a reserved built-in PCB DRC slot, hence fifteen custom pre validators, and sixteen custom post callbacks. The built-in runs first when enabled; custom callbacks run in registration order.

Settings, registrations and bounded diagnostics are transient, shared through cloned handles, preserved across native New/Open/import and undo/redo, and absent from native projects and event logs. A checked configuration generation changes only for actual successful registration/removal/configuration changes; exact no-op leaves it unchanged. Refuse generation overflow before changing configuration. Never serialize closure implementations.

## Pre-commit behavior

For each changed outer transaction, after original coalescing and before TxId allocation, history/redo/selection/events/document status changes, invoke the enabled pre validators once. The immutable borrowed context includes candidate Project, coalesced deltas, exact source cursor, origin, label and operation kind. It permits examining the complete candidate without making another project copy. It exposes no mutable engine or model access. Generic trusted validators have no new universal project-size ceiling: they borrow the existing candidate, and their own computation/allocation is trusted code.

A Result refusal, caught unwinding panic or enabled pre-boundary admission failure inverts the original transaction deltas. Preserve complete Project/selection/session cursor/history/log/native path/dirty state/native bytes, redo contents, next TxId and AutoDRC generation/report. Only transient hook diagnostics may record the refusal. Stop at the first failed pre validator. The original Result error type gains an actionable hook ID/reason without claiming the command committed. A private branch whose merge is vetoed remains inspectable/discardable, with its original candidate/revision/lease and live source unchanged; do not remove it before commit succeeds.

No-op transactions skip all validators and post callbacks and preserve original redo behavior. Preserve the existing no-op TxId consumption; a veto consumes no TxId. A batch validates its final coalesced candidate once, so an atomic repair can succeed even if an intermediate subcommand violates DRC. Original command validation still runs normally. Do not change command-panic semantics outside these callback boundaries.

Undo and selective undo remain non-vetoed escape paths and produce post facts. Redo and selective redo validate the complete candidate before changing either history stack or emitting; refusal restores exact project/stacks/cursor/status and original transaction identity. Successful redo uses its original TxId and emits exactly one original event. Commands are not re-executed to redo.

## Immutable post facts and delivery

Capture one immutable fact per successful changed apply/undo/redo, with exact project ID, committed cursor, source cursor, TxId, change kind, origin, label, configuration generation and fixed per-delta-kind counts. It is a summary, not a full Project/Part/Sheet snapshot or unbounded object-ID list. Retained label and origin ID each require at most1024 UTF-8 bytes; check borrowed lengths before copies when a changed commit has registered post observers. A metadata refusal occurs before apply/redo publication and rolls back as above; undo remains available and may explicitly abbreviate oversized legacy origin/label with an abbreviation flag in its post fact. Never silently present abbreviated text as exact. Counts and operation identity remain exact.

Snapshot callback IDs/order and Arc ownership with the fact. Later registration changes cannot reattribute an already committed fact. EngineHandle drains and delivers after releasing engine and native-file locks, before returning the ordinary operation result; callbacks can read current engine state, which another thread may already have advanced. Facts always describe their original commit. Do not hold configuration/diagnostic locks while invoking user callbacks. Repaint/session notifications and AutoDRC scheduling remain once per successful original change, even if a post callback fails.

Standalone Engine exposes a drain API for pending post deliveries so its caller can invoke them after releasing any external lock. The queue holds at most32 fact/callback snapshots. A changed apply/redo that would overflow refuses before publication; undo remains possible and records an explicit bounded notification-drop diagnostic if this exceptional standalone queue is full. EngineHandle drains every operation, including its Result path. No background or detached callback queue is introduced. No-op and failed commands generate no post fact. Document replacement, native save, selection, agent attention, configuration and private candidate edits remain separate non-design actions; they do not masquerade as design commits.

Post callbacks return Result; failure or caught unwinding panic cannot roll back a committed transaction or suppress later callbacks. Record a bounded failure with callback ID and original cursor. Keep only the latest64 diagnostics, each message at most1024 UTF-8 bytes, truncating at a valid character boundary with an explicit truncation flag. Unknown panic payload disposal is protected against a second unwinding panic; do not claim to recover aborting destructors. Diagnostics never trigger hooks recursively.

## Enforced callback re-entry

Use a thread-local callback-phase guard before the first relevant shared lock. During pre callbacks, captured-handle reads and writes refuse; reading the borrowed candidate is the supported route. During post callbacks, finite ordinary state snapshots are allowed (they may wait for a peer thread holding the engine mutex; this does not promise try_lock admission), while synchronous writes, configuration changes, native publication/lifecycle operations, branch mutation and attention mutation refuse before taking their locks. Waiting observation APIs such as watch_events/watch_auto_drc_events also refuse inside callbacks, preventing a callback from waiting on a future change that its own operation blocks. A refused operation makes no state/file change. A trusted callback may catch a refusal and continue; its explicit Result still decides the callback outcome.

Fallible APIs return an actionable re-entry error. Existing infallible APIs may raise a dedicated local panic caught by the enclosing callback boundary; do not silently change their signatures or block on the mutex. Inventory central Handle::lock/mutate, direct engine locks in agent_presence and branch wake, native-file locks, branch/presence stores, mode/configuration setters and waiting observations. Existing read methods that opportunistically purge transient stores must either use an inert bounded callback observation or refuse explicitly. Do not call mutation-capable repaint listeners under a callback guard while holding any shared lock.

This guard applies to the callback thread and does not sandbox arbitrary trusted Rust. A callback can allocate, loop forever, abort, or spawn/join a thread that waits on the held engine lock. There is no safe hard execution deadline or claim to prevent all cross-thread deadlocks. Never use detached timeout workers that continue after admission retires. Keep the original MCP writer admission alive until all synchronous callbacks finish.

Reject any supported violation, checker error/panic, report truncation/incomplete_reason, excluded part or truncated exclusion details. Unsupported feature classes listed in checks_not_performed remain disclosed; this gate enforces only the supported checks, not total manufacturability. Enabling config does not validate or mutate the current project. Existing invalid designs may require atomic repair; unrelated edits can still refuse. Undo stays available.

Keep current AutoDRC as independent post-commit background observation. A veto neither invalidates nor schedules it; a successful design change invalidates once. Preserve engine-to-AutoDRC lock order and original worker lifetime. Hook configuration does not change its settings.
