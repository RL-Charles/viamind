# Bounded connected schematic symbol translation

## Public sources and existing foundation

Behavioral source: the official [KiCad 9 Schematic Editor manual, Working with symbols](https://docs.kicad.org/9.0/en/eeschema/eeschema.html#working-with-symbols), retrieved 2026-10-11. It distinguishes moving a symbol from dragging it with its connected wires, describes a configurable mouse drag gesture, and identifies Escape as operation cancellation. Its electrical-connections section describes exact endpoint and junction contacts. These publicly described behaviors motivate an independent implementation; no source code, icons, assets or implementation algorithms are copied.

Existing Viamind contracts are authoritative for topology: `doc::schematic::Symbol::pin_position` applies mirrored local X, exact quarter-turn rotation and translation in integer Nm. `engine::schematic_connectivity` computes the actual bounded flat-sheet/global-label graph, with endpoint/T contacts and explicit junctions; interior crossings alone do not connect. The existing canvas pans or selects, and the coordinate property editor changes symbol pose without adjusting wires. `draw_schematic_wire_polyline` creates new cardinal wires. This increment adds a useful connected rearrangement operation, independently of compact sidebar reachability, mask/paste, mechanical holes, buses and hierarchy.

Initial immutable implementation base is T118 `ac03d0f40e10221ad35191120780c5d5fced17e4`; all earlier proof retains its own source identities. This specification is for T125 under S041 and requires independent approval before Rust edits.

## Supported operation and exact geometry

Translate exactly one explicitly selected symbol UUID on one sheet by signed integer `delta: Coordinate`. Preserve its rotation, mirroring, body, pins, IDs, reference/value/footprint and package membership. A unit belonging to an explicit package may move independently in pose; shared package metadata and complete physical PCB ownership remain unchanged. Do not change PCB Parts, pin-to-pad links, annotation, labels, junctions or other symbols.

Require at most256 pins on the moved symbol, with distinct transformed source pin positions, and at most256 incident wires. A supported attachment is an original wire endpoint exactly coincident with one moved pin. An incident original wire must be a nonzero horizontal or vertical segment. Refuse a moved pin lying strictly inside any wire, a moved pin coincident with a label/junction or another symbol's pin, and any ambiguous/unsupported attachment before planning. Multiple original endpoint wires at one moved pin are supported if the complete graph proof below succeeds. An unconnected pin may move, subject to the same graph proof.

For each original wire, in ascending UUID order:

1. Neither endpoint attached to a moved pin: retain it byte-for-byte.
2. Both endpoints attached to moved pins: translate both endpoints by the same delta, preserving the original wire UUID and endpoint ordering.
3. Exactly one endpoint attached: hold the other endpoint fixed. If the new endpoints share X or Y, retain one segment and the original UUID (orientation may change). Otherwise create one orthogonal bend. For an originally horizontal wire the bend is `(new_moving.x, fixed.y)`; for an originally vertical wire it is `(fixed.x, new_moving.y)`. The fixed-end-to-bend segment retains the original wire UUID and its original start/end role; the bend-to-moving segment receives one fresh UUID on commit. Zero-length segments are never emitted.

All arithmetic uses checked integer Nm; validate new symbol origin, transformed pin endpoints and bend coordinates through the native ±10000mm coordinate validator. No floating geometry is stored. Native integer endpoints may use existing off-grid positions. Desktop snapping determines only the requested integer displacement: snap the proposed symbol origin to a positive explicitly shown grid, with documented nearest-grid ties away from zero, then subtract the original origin. The coordinate fallback accepts exact integer Nm through the same request.

Do not delete original wires or silently replace their identities. At most256 new segments and512 changed result segments are permitted. Refuse a zero-length collapsed original wire, invalid native candidate, overlapping identity, exhausted count budget or unsupported geometry atomically. A zero displacement is a validated no-op with no history/event/native change.

## Actual connectivity proof

Use the existing production schematic graph algorithm on the complete bounded schematic before and after the candidate edit. This includes other sheets and global/power labels. A page of nets, inferred visual attachment or number of nets alone cannot authorize an edit.

Canonicalize every original graph member by its stable `(sheet UUID, member UUID, kind)` anchor, including original wires, pins, junctions and labels. For each component, sort all original anchors and record its original label UUID/name/scope facts. New bend-wire UUIDs are not canonical anchors. Require the complete set of original anchors and their exact component partition and label facts to remain identical. This catches a pin or old wire disconnecting, merging existing components, splitting a component, and changing label-scoped connectivity even if the total net count stays constant. Derived net IDs and positions are not equality oracles: the native graph can derive a different ID from a new segment, while expected geometry intentionally moves.

Each new segment must join the component of its originating original wire; no new isolated unanchored component is allowed. A graph error, unsupported/incomplete coverage needed for this proof, missing anchor, exhausted candidate budget or unequal partition refuses the whole edit. This is preservation of the current supported native flat graph, not electrical correctness, ERC/DRC acceptance, routing optimization or physical continuity certification. Existing inconsistent named-net facts may be preserved exactly; no name is inferred or repaired.

## Shared request, guards and result

Add a strict shared `DragSchematicSymbol` command with fixed-size fields: expected project UUID, full source event cursor, sheet UUID, symbol UUID and signed integer displacement. Unknown fields, null/malformed identities and missing guards refuse. No caller-supplied candidate sheet, topology-pass flag or authorization report is accepted. Recompute the plan and actual proof at apply from the guarded live source. The complete cursor must match before worker admission/capture and again before mutation; selection events may therefore invalidate an old preview. The engine command remains the only mutator and emits one atomic sheet delta with all existing/new wire IDs retained in history. Ordinary command hooks still validate the final candidate; veto rolls the operation back completely.

Expose a separate observation `preview_schematic_symbol_drag` using the same typed request and planner. Its result identifies project/full source cursor, symbol/source and target pose, changed original wire IDs, bounded replacement segment coordinates with deterministic local new-segment ordinals, counts and explicit native-graph-preservation scope. It allocates no permanent IDs or history. Final apply allocates new globally unique wire UUIDs only after successful bounded preflight/proof, under normal native identity validation; it does not trust a preview result supplied by a client. A preview never promises future acceptance if a peer changes the source.

Preview is admitted in all agent modes as observation. Apply is a Live writer and is unavailable by default in Approval and ReadOnly, including the immutable startup ceiling; do not add it to private-branch allowlists or implicit Approval preparation in this increment. Existing command catalog/UI action parity and generated reference must include both tools. Hook pre-callbacks refuse preview entry before reserving a slot and captured preview execution before taking the engine mutex; post callbacks may observe committed source normally.

## Borrowed budgets, copies and workers

Before allocating plan/reference tables or cloning selected data, apply existing borrowed selected-sheet/global validation budgets and the stricter complete graph budget: at most1000 sheets;10000 total graph objects including sheets, symbols, pins, wires, junctions, labels and package-member records;2MiB aggregate schematic text. Existing per-string4096-byte and selected-sheet10000-object/10000-pin limits also apply. Global native validation remains bounded to100000 combined project/board/schematic identities and4MiB schematic text, including planned new segment IDs. Object and member counts are checked before scanning text or cloning.

The planner owns bounded schematic-only data; do not clone `Project` or any board Parts, sourcing strings, artwork or manufacturing state. The source graph capture and candidate schematic may each hold one bounded schematic copy; a selected-sheet replacement copy must be included in that fixed bounded envelope. Do not introduce an additional full project clone. Keep immutable original anchors and named facts bounded by the same counts/text before secondary copies. Charge planned additions against both graph/native limits before allocating or applying. The whole operation refuses rather than truncates or paginates.

Use one cumulative1million exact contact/candidate-visit budget across source and candidate graph work, not an independently reset budget per pass. The engine's existing spatial broad phase is only a candidate accelerator; predicates remain native exact integer geometry. Bound result serialization to2MiB with append precharge. Two nonwaiting shared process slots bound actual planner work; a preview owns its slot through capture/proof/serialization and actual worker retirement, including caller cancellation. A command may reserve nonblocking admission inside its serialized engine apply; there is no wait while holding the engine lock. Fallible named desktop spawn leaves no pending state on failure. No deadline, throughput or frame-cadence claim is made for bounded synchronous engine commit.

## Desktop behavior

Provide an explicit connected-drag mode for a selected symbol and a scrollable compact coordinate fallback. Capture the guarded source at drag start. Local pointer motion paints the proposed symbol and deterministic attached-segment geometry from that bounded source; it does not call the heavy graph planner every frame and does not modify model/history. Show that this is an unvalidated local preview. Escape, tool/sheet changes, document lifecycle changes or stale full cursor cancel the local draft without a transaction.

At release, run one retained bounded preview worker. While pending, disable duplicate apply and conflicting local tools, and poll even if the dialog is hidden. A refused preview keeps readable errors and permits an explicit retry on a freshly captured source. A successful preview enables an explicit apply action using its original guarded request; apply recalculates the proof in the command engine. This two-stage gesture avoids treating a painted preview as a connectivity guarantee. The coordinate fallback uses the exact same preview/apply path. Committing performs one undoable operation; source invalidation between preview and apply refuses unchanged state. Desktop completion identifies the original and committed cursor and whether subsequent edits have occurred.

Preserve existing symbol property edits, wire tools, annotation, package selection and camera pan controls. This increment does not add multi-symbol dragging, rotation during drag, junction/label dragging, arbitrary diagonal rubberbanding, automatic junction insertion, cleanup/rerouting of surrounding wires, buses or hierarchical scope inference. No schema/library/native-version change is needed; absent/default project bytes stay unchanged.
