# Trusted agent approval and desktop mode switching

Ticket T-0117, parent S-027. Initial source stack is T113 `842e9c1` atop frozen T112 `b761793`; only this ticket's commits will be transplanted onto the final multi-unit/package stack before combined verification. This public behavior contract precedes implementation and requires independent approval. No Rust changes belong to this draft.

## Public sources and independent behavior

The public [MCP tools contract](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), read 2026-10-11, describes discoverable named tools, structured results, untrusted annotation hints, human control and tool-list change notifications. The [MCP lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), read on the same date, separates initialized connections and negotiated server capabilities. Neither specifies Viamind's approval transaction design. The admission policy, proposal lifecycle, guards and limits below are independently designed from those public interfaces and existing original Viamind commands. No proprietary assets, code or library data are used.

## Exact scope

A trusted human can choose Live apply, Approval, or Read only for every agent endpoint attached to one application EngineHandle. Default is Live apply. Approval exposes explicitly audited observations and bounded original T113 PCB candidate preparation; direct live mutations and file publication refuse before their handlers. The human reviews actual old/new PCB geometry and accepts one exact candidate as one undoable transaction or rejects it. Unsupported edit families remain unavailable to agents in Approval; no schematic, assembly, library, lifecycle or filesystem proposal is silently accepted or converted to a partial PCB proposal.

This enforces this application's MCP admission and process-local proposal ownership. It does not authenticate remote clients, isolate OS/filesystem access, police another Viamind process or restrict trusted internal callers of EngineHandle. Human desktop editing remains ordinary live editing in all modes. Reading supported existing files is allowed for audited observations. Enforced approval is distinct from T113's voluntary sandbox in Live apply.

## Shared state and immutable restriction

One controller belongs to the shared EngineHandle and survives New/Open/undo/redo, with mode, monotonically increasing policy generation, immutable startup lock and active admitted writer count. Mode is session configuration, outside Project, history, native/event envelopes and design cursor. Mode changes preserve full project, selection, native bytes, active path, dirty status and automatic DRC state. A read-only mode observation returns mode, generation, fixed restriction and admitted proposal command names; no agent tool changes policy.

Default live constructors preserve existing behavior. Add `--agent-approval` for desktop HTTP and headless stdio, set before exposing any endpoint. It is mutually exclusive with `--agent-read-only`, and follows the existing agent-read-only prohibition on demo/no-MCP/save-as/CLI export combinations before opening input/output/windows/listeners. Headless approval supports candidate preparation and observation; acceptance requires a trusted human desktop attached to that application, so a purely headless approval process cannot grant itself acceptance.

Preserve the existing immutable `--agent-read-only` upper bound: it cannot be lifted by a registry clone, later registration, tool call or desktop selector. Its visible selector explains the startup lock and disables upgrades. Existing explicit `ToolRegistry::read_only()` remains an immutable per-registry observation ceiling. Read only chosen by a human in an initially live/approval process can later be changed by that human. A fixed endpoint ceiling always wins over the current controller mode.

## Default-deny classification and dispatch

General registration is a live writer, including future/unknown tools. Only trusted host code marks an observation, supported private-candidate operation, or exact branch merge. Client input, `_meta`, reported name, Origin text, tool annotations and description never classify effects or permit a policy transition. Registry clones and subsequently registered tools retain the same shared policy and fixed restriction. Audit every engine-host and external registration, including new package APIs when they land.

- Live apply advertises and admits ordinary existing tools, private PCB candidates and agent-owned exact merges.
- Approval advertises audited observations plus `create_pcb_branch`, `apply_pcb_branch`, `inspect_pcb_branch`, and `discard_pcb_branch`. `list_pcb_branches` and `get_pcb_branch_diff` remain observations. Direct model/history/selection/lifecycle/auto-DRC-config changes, agent `merge_pcb_branch`, native save, exports, detached library/job save, conversion publication and every other writer are hidden and directly refused before handler decoding, snapshot capture, worker creation, mutation or I/O. Original branch connection ownership applies to all private-candidate operations.
- Read only exposes the existing audited observation whitelist, with all five private-candidate handlers and agent branch merge unavailable.
- Existing SVG/PNG mixed views retain only in-memory output in both restricted modes. Remove `path` from advertised schemas and reject every supplied top-level path, including null/wrong types, before invoking the handler. In Live apply their original schema/behavior remains unchanged. Every Live mixed-view invocation with a top-level `path` present is a writer for admission and transition accounting, conservatively including null or malformed path values, despite the tool's observation registration. Its token remains owned through rendering and actual publication completion. A path-absent in-memory invocation remains an observation. Restricted modes reject path before invoking the handler or worker. Do not generalize this exception to other writers.

Discovery, lookup, counts, PNG output selection and dispatch use the same effective policy. Calls cached by an agent from an earlier mode are rechecked at dispatch; hidden names receive the existing protocol unknown-tool failure. Initialized connections receive tool-list change notification after a successful policy change, using negotiated listChanged capability. Initialization instructions explain the effective mode at initialization, and the current mode observation remains authoritative after a transition. No unrequested notification payload exposes private candidate geometry.

## Cancellation-safe admission and human transitions

Mode transition and admission serialize through one short controller lock. A non-observation call (including every Live mixed-view call with a top-level path present) rechecks current classification and policy and obtains a retained admission token before invoking any handler. At most 16 non-observation calls per controller are admitted concurrently; further calls fail immediately without starting work. Observations retain their existing independently bounded readers. No lock is held while running a handler, blocking worker, engine operation, notification or UI render.

A human mode change fails immediately with the actual busy count while any admitted non-observation operation is unfinished. It is not queued, automatically retried or treated as successful. After every admitted operation and any owned publication worker have completed, the human may retry. A successful transition increments generation once and applies atomically to every shared endpoint. Selecting the current mode is an unchanged no-op. Bound generation overflow by refusing a transition rather than wrapping.

Dropping/aborting an MCP awaiter, disconnecting its HTTP session, or shutting down an endpoint runtime must not drop admission while an actual worker can still mutate or publish. The implementation must retain the complete admitted handler until completion and retain its token across all internal worker awaits, independently of transport runtime lifetime. A process-lifetime dedicated execution runtime for admitted handlers is one permitted design; merely wrapping an abortable request future or dropping a join handle while its child worker runs is insufficient. Audit all non-observation handlers for detached publication and ensure their completion means owned workers finished. Preserve original trusted CallContext identity. Panics/spawn failures report errors and release tokens after work is finished; no unbounded task or input queue is added. Application exit ends the process and is outside runtime mode switching.

A test must hold an actual publication worker at a deterministic barrier, cancel the real caller, shut down its endpoint/runtime, and prove a human transition still refuses until the worker finishes and its token retires. A second test must race human transition against admission and prove exactly one legal ordering with no old-mode writer entering after a successful restriction. Test synchronization observes actual lifecycle boundaries rather than stealing nonwaiting permits through polling.

## Human review and compact workflow

Expose trusted mode controls in the desktop with a persistent visible mode label at 640x400. Show startup lock, busy/refusal state and supported proposal scope. Options cannot be triggered through MCP. A successful mode choice neither writes nor accepts an existing candidate.

Approval uses the original T113 Board → Agent branches shared review controller and real green/red ghost geometry. Human actions are labeled Accept proposal and Reject proposal (the same exact merge/discard semantics); Live apply retains its existing Merge/Discard affordance. Show creator, source/full cursor, revision, changed count, expiry and explicitly unchecked DRC status. Accept is disabled on stale/busy source and validates project/full cursor, candidate revision and before-values again under the engine lock. Successful acceptance preserves generated IDs, emits exactly one normal original-origin transaction and schedules existing automatic DRC. One undo/redo restores exact original/merged geometry. Reject changes no live document/session/native state. Peer edits/New/Open continue to stale and clear incompatible ghosts without rebasing. Source mode changes do not renew candidate leases or silently accept anything.

Human inspection can view every proposal; agent inspection/apply/discard remains creator-only. No approval API permits a forged human actor. A local trusted human calling the existing shared UI action is the sole acceptance path while Approval is active. Ordinary human actions remain available in Read only and immutable startup-read-only mode.
