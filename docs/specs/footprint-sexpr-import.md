# Bounded standalone footprint S-expression conversion (T89)

## Public sources and independent scope

This specification precedes implementation. Sources are the official public
[standalone footprint format](https://dev-docs.kicad.org/en/file-formats/sexpr-footprint/)
and [common S-expression format](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/),
consulted 2026-10-11. The latter defines footprint/pad attributes, local coordinates,
canonical layers, degree angles and nanometre resolution. Viamind's existing
[native library contract](footprint-library.md) defines the conversion target.

A `.kicad_mod` file describes one named detached footprint. Libraries are folders
of such files; this increment reads one explicit source file and writes one new
native library file. It does not enumerate folders, download or install assets,
resolve environment variables/models, read external libraries or copy any external
application code, library assets or UI. Original fixtures are authored from these
public format definitions. S079 full project/corpus acceptance and broad S083
fidelity acceptance remain open.

## Supported exact local geometry

- One top-level `footprint` containing one quoted name, a supported tested date
  header (`20221018`, `20240108` or `20241229`) and explicit front `F.Cu` layer.
  These are tested header variants, not a universal versions 7–9 compatibility claim.
- Between one and 1024 pads. Each has a unique nonempty trimmed number,
  `smd rect`, exact local `(at x y [0])`, positive exact `(size width height)`
  and layers containing exactly `F.Cu`, optionally `F.Mask` and `F.Paste`.
  Repeated layers, arbitrary/wildcard copper and extra semantic attributes block.
- Native names/numbers are at most128 characters with no controls. Native local
  coordinates are within ±10000mm; sizes are greater than0 and at most10000mm.
  Pad order is source order. Duplicate numbers are rejected rather than merged.
- Decimal millimetres convert to integer Nm without floats. Nonzero sub-Nm
  precision, scientific notation, nonfinite numbers, overflow and out-of-range
  geometry reject. Trailing zero decimal places are exact and may be accepted.
- Source local numeric coordinates are retained in the native local frame.
  There is no translation, rotation, mirroring, inferred anchor or guessed angle
  convention. A footprint-level `at`, if present, must be exactly origin/zero
  rotation and is reported omitted; nonzero placement blocks conversion.
- Only zero-angle pads are represented. Other shapes, drill definitions,
  through-hole/connect pads, zones, net ties, thermal/clearance/paste/mask
  overrides, back-side footprints and electrical graphic copper block export.
  Unsupported pad attributes never silently become ordinary rectangular copper.
- The native target is `viamind-footprint` version1: a name plus numbered local
  pad rectangles. The existing strict target validator must pass before export.

## Detached identities and nets

The output library has no project UUIDs, pad UUIDs, board placement, schematic
links or nets. A source UUID/tstamp, when present, must be valid, nonnil and unique
within the source; it is retained only as report provenance and explicitly omitted
from native output. Missing source UUIDs are permitted because the target is a
reusable definition, not a placed board component.

A pad with no net is detached. An explicit `(net 0 "")` is accepted and reported
omitted as an unassigned marker. Any other net assignment blocks conversion;
meaningful source connectivity is never silently discarded. Board-only linkage
such as a schematic `path` blocks conversion instead of inferring a component.

No object IDs are generated by conversion itself. Later explicit native
`apply_footprint` remains the existing guarded command: matching numbers retain
current pad IDs/nets, new numbers receive fresh IDs and no net, removed pads
leave, and component placement is retained. Import does not automatically apply
or mutate any selected project component.

## Fidelity contract

Every parsed list receives a deterministic source path, original byte offset,
original token, optional source UUID, disposition and actionable reason.
Classifications use the T83 report contract:

- Imported: exact supported name, local rectangular pad geometry and numbers.
- Omitted: recognized header/generator/edit metadata, property/text fields,
  noncopper graphic art, source IDs, empty net markers and optional mask/paste
  layer memberships. Each omission is explicit; source graphical/manufacturing
  fidelity is not retained by the native rectangular-pad library.
- Blocked: unknown semantics, unsupported pad geometry/electrical attributes,
  copper or Edge.Cuts graphics, zones/net ties, nonzero placement, meaningful
  net assignments and unsupported canonical layers. Blocked descendants remain
  classified rather than disappearing from the report.

Recognized noncopper graphics must have an explicit canonical noncopper layer.
Their entire bounded attribute subtree is omitted as art, never treated as native
copper or board geometry. Native setup/rule defaults are not source rules.
`full_fidelity` is always false. A report with any blocked item cannot export.
A structurally malformed or resource-excessive input rejects with an error;
no partial output file or truncated fidelity claim is published.

## Explicit resource bounds

The source is a UTF-8 regular file no larger than1MiB. Check both path length
(≤4096 encoded bytes before filesystem operations) and descriptor metadata.
Safe nonblocking Linux opening plus opened-descriptor regular-file validation
must reject raced FIFOs/devices/directories without waiting for a writer.
Reads are capped at1MiB+1 and must detect observed read-time changes.

Use the same independent bounded tokenizer as T83, with no parser based on
external application source. Before allocating unbounded structures enforce:
list depth≤32; tokens≤100000; parsed nodes/report items≤20000; each decoded
string/token≤4096bytes; aggregate decoded text≤1MiB; electrical pad count≤1024.
Report reasons use bounded paths/constants rather than repeatedly cloning long
source tokens. Output is bounded by the existing native1MiB envelope validator.
No quadratic geometric fitting or polygon flattening is performed.

## Shared engine and file lifecycle

`preview_footprint_conversion` takes one source path, reads/parses outside the
engine mutex, and returns absolute path, exact source SHA256, validated detached
native footprint (only when supported), source fidelity and `can_convert`.
It never changes project, cursor, history, selection, dirty state or active path.

`convert_footprint_file` takes the source path, expected exact lowercase SHA256
and explicit destination path. It rereads/reparses rather than trusting cached
native JSON from a client. Changed source bytes, malformed/blocked geometry,
empty/excessive paths, source/destination aliases, existing destinations and
symlinks reject. The destination is one explicit new native library file;
atomic no-clobber publication preserves all preexisting bytes.

Serialize and sync bounded output in a temporary file before publication. Under
the existing native-file lifecycle guard, compare the destination with the
current active native project absolute/canonical path and atomically publish.
Filesystem I/O remains outside the engine document mutex. A concurrent native
open/save cannot race active-path protection. Dirty project work is allowed
because detached conversion makes no project changes; all session fields remain
unchanged. Source and other library files are never overwritten.

The existing native footprint loader is exercised when reusing the converted
file. Its bounded read should use the same safe nonblocking regular-file opening
and path cap, closing its existing metadata/open FIFO race without changing
native JSON semantics. This small related hardening is tested independently.

## Accessible desktop workflow and parity

A separate `Convert footprint S-expression…` form exposes source, explicit new
native output path, Preview, a virtualized fidelity report and explicit Convert.
Every action dispatches matching shared engine/MCP methods. The form may open
while component drafts exist; conversion never applies geometry or cancels drafts.
Users subsequently choose the existing native footprint import/application flow.

One retained background receiver bounds outstanding work. Source/output changes,
close/reopen and context replacement invalidate displayed results; stale workers
cannot enable conversion for a different path. Fallible spawn/disconnection are
actionable. Output completion names its exact source snapshot and new library
path. Outer scrolling and responsive widths keep Convert/errors reachable at
640×400. Long reasons retain full tooltip/JSON values.

## Required evidence

Original asymmetric odd-Nm fixtures, optional source IDs/unassigned markers,
quoted strings, header variants, duplicate numbers/IDs, unsupported geometry and
all parser bounds. Native round-trip of detached output; two existing components
applied separately prove matching-number retention and fresh distinct new pad IDs
without inferred nets. Source changes, existing/symlink/native destinations,
controlled FIFO races and concurrent publication/native lifecycle guards preserve
bytes and complete engine sessions. Actual desktop input/worker tests, real
independent MCP clients, production stdio and desktop HTTP, readable normal and
compact native captures, fmt/strictClippy/workspace tests/build and durable
revision/binary provenance are required before submission.
